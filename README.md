# sensor-hal-go

纯本地、零外部依赖的加速度传感器驱动与硬件抽象层（HAL）。硬件由**内存映射
寄存器总线**模拟，不需要真实硬件或外部服务即可完成设备探测、初始化、采样、
寄存器映射版本兼容判定与电源状态切换。

- `bus`：内存寄存器总线（16 位寄存器、单读/单写/突发读、事务日志、确定性故障注入）
- `sensor`：设备驱动（探测/初始化/采样、版本兼容、写后回读、仅读重试、电源状态机）、
  以及确定性的模拟设备模型 `SimDevice`
- `hal`：对外门面（归一化错误码、并发串行化采样、挂起取消在途操作、长时连续采样流）
- `observe`：面向长期运行的观测层（容量有界的近期采样环、增量游标读取、
  有界失败记录，采集与查询互不阻塞）

## 1. 适用总线模型

- 寻址：8 位寄存器地址，16 位寄存器值。
- 事务：`Read(addr)`、`Write(addr,val)`、`ReadBurst(addr,n)`。
  所有事务在总线单锁内串行完成；**突发读在同一临界区内取数，不存在撕裂读**。
- 设备模型：`bus.Model` 挂接在总线上模拟设备行为（电源状态机、按 ODR 产生数据、
  OVERRUN/RCAL 状态位）。模型可实现 `bus.WriteGate` 在掉电时拒绝写入。
- 可观测：每次事务都记录到 `Log()`：序号、类型、地址、值、故障、时间戳，
  单测通过 `-v` 打印全部读写激励；驱动还会打印 `PROBE/SAMPLE/STATE` 迁移日志。
- 故障注入：`FaultRule{Kind, Addr, Times, Fault, Delay}` 可精确注入
  `TIMEOUT / REJECT / CORRUPT`，`Times` 控制前 N 次命中（用于“先失败后成功”）。
  - `REJECT`：事务被拒绝，寄存器不变、设备模型不触发；
  - `CORRUPT`：写时设备收到的是取反值（读回必然不一致），读时返回取反值；
  - `TIMEOUT`：等待 `Delay` 后返回 `bus.ErrTimeout`，等待可被 ctx 取消。

## 2. 版本兼容规则

版本编码为 `Major<<8 | Minor`（寄存器 `0x01`）。驱动编译期版本为 `2.1`，
判定只取决于入参，结果确定、拒绝原因彼此可区分：

| 设备情况 | 结论 | 原因（CompatReason） |
| --- | --- | --- |
| 芯片 ID 未知 | 拒绝 | `UNKNOWN_CHIP` |
| 版本寄存器为 `0xFFFF` | 拒绝 | `VERSION_UNREADABLE` |
| Major 不同（更新或更旧） | 拒绝 | `MAJOR_MISMATCH` |
| Major 相同，设备 Minor 更旧 | 拒绝 | `DEVICE_TOO_OLD` |
| Major 相同，Minor 相同或更新 | **接受** | `OK` |

- **较新 Minor 接受**：Minor 升级只允许在寄存器映射尾部追加字段，
  `Config.ODR/FSR` 等既有字段的地址与语义不变，因此不会静默改变既有语义。
- **较新 Major 拒绝**：Major 变化允许重新定义既有字段，驱动无法保证语义一致。
- 不兼容时 `Probe/Init` 均返回 `KindIncompatible`，设备不会进入 ACTIVE。

## 3. 电源状态迁移

```
                 Init(合法配置+版本兼容+回读一致)
   OFF  ───────────────────────────────────────────► ACTIVE
    ▲     PowerOff(0x03=0)             Suspend(0x03=POWER|SUSPEND)
    └──────────────────────────┐    ┌───────────────────────────┐
                               ◄────┘                           ▼
                             ACTIVE ◄──────────────────── SUSPENDED
                                  Resume(0x03=POWER)
```

- 仅 `ACTIVE` 可采样。
- **挂起期间**：`Sample/Init/Probe/Suspend` 立即返回 `SUSPENDED`，
  不发起任何总线事务、不返回陈旧数据。
- **Resume**：先上电，再读配置签名寄存器 `0x1F`（`0xC0FE`）。
  签名丢失（突发掉电）则按驱动保存的配置**完整重新初始化**，
  不沿用内存里的旧状态；签名仍在则直接回到 ACTIVE。
- **PowerOff** 幂等；掉电后只有重新 `Init` 才能使用，采样返回 `POWERED_OFF`。
- 迁移过程中的总线失败不会产生虚假状态迁移（如挂起失败仍停留在 ACTIVE）。
- `SimDevice.SimulatePowerLoss(bus)` 可确定性模拟挂起期间的突发掉电
  （Ctrl/ODR/FSR/签名/数据/状态寄存器全部复位）。

HAL 层额外保证：`Suspend/Shutdown` 会**取消在途采样**，因此不会被长采样阻塞；
采样通过容量 1 的令牌串行化，获取令牌本身也可被 ctx 取消。

## 4. 错误分类与重试/副作用规则

根因在进入对外接口前归一化，不同调用路径遇到同类根因得到同一错误码。

| 根因 | sensor.Kind | hal.Code |
| --- | --- | --- |
| 总线超时 | `TIMEOUT` | `TIMEOUT` |
| 设备拒绝（如下电时写） | `REJECTED` | `REJECTED` |
| 写后回读不一致 | `READBACK_MISMATCH` | `READBACK_MISMATCH` |
| 配置非法（枚举之外） | `BAD_CONFIG` | `BAD_CONFIG` |
| 版本不兼容 | `INCOMPATIBLE` | `INCOMPATIBLE` |
| 挂起中访问 | `SUSPENDED` | `SUSPENDED` |
| 掉电访问 | `POWERED_OFF` | `POWERED_OFF` |
| 其他 IO 错误 | `IO` | `IO` |
| 调用方取消/超时 | `CANCELED` | `CANCELED` |

重试与副作用约定：

- **只有读事务允许重试，且只对总线超时重试**（默认 2 次额外尝试，共 3 次）；
  拒绝、取消、不兼容等立即返回。终态错误带 `Attempts` 计数，`Retryable=false`，
  失败不被重试掩盖。
- **写事务一次定音、绝不重试**，因此不会产生重复写副作用；每次写后立即读回校验，
  不符即 `READBACK_MISMATCH`（线上被 CORRUPT 时设备存的是取反值，读回必然失败）。
- 非法配置在触碰总线之前就被拒绝（验证用例断言总线日志为 0 条）。

采样结果 `Sample` 带：墙钟时间戳 `T`、三轴 `X/Y/Z`、配置快照 `ODR/FSR` 与
质量标记 `QOK / QOverrun（旧帧被新帧覆盖）/ QNeedsRecal`。
数据就绪采用“读状态位 → 休眠 `PollInterval` → 再读”的有界轮询
（默认 1ms 间隔、200ms 上限），**没有忙等**。

## 5. 并发与长时运行

- 总线事务串行、突发读原子；驱动全部方法在互斥锁下推进状态机。
- HAL 同一时刻只允许一个采样事务在途（并发 `Read` 被串行化），
  在 `-race` 下验证无数据竞争，且连续帧序列值严格递增，不会两调用读到同一帧。
- `Stream(ctx)` 只启动一个 goroutine、输出无缓冲通道；帧间释放采样令牌，
  挂起/关电可插入。遇到挂起/掉电等终态时下发一条错误并关闭通道，不空转；
  ctx 取消后 goroutine 必然退出、通道必然关闭，测试断言 goroutine 数量回落到基线。

## 6. 长期运行观测层（`observe`）

`observe.Observer` 包在 HAL 之上，专为连续跑几天甚至更久的边缘采集进程设计：
后台连续采样，把最近的帧与失败记录留在**容量固定**的内存环里供随时复盘，
不依赖外部存储、不随运行时长增长。

最小用法：

```go
obs := observe.New(h, observe.Options{
    SampleCapacity:  1024, // 近期采样条数上限（默认 1024）
    FailureCapacity: 256,  // 失败记录条数上限（默认 256）
    RetryInterval:   20 * time.Millisecond,
})
ctx, stop := obs.Start()   // 后台 goroutine 连续采集
defer stop()
defer obs.Wait()

snap := obs.Recent(100)         // 最近 100 帧快照（老→新）
b    := obs.Since(cursor, 50)   // 游标之后的增量帧，cursor = b.NextCursor
fl   := obs.Failures()          // 最近的失败记录
st   := obs.Stats()             // 容量/当前条数/累计计数
```

### 6.1 容量规则（长时间占用平稳）

- 采样与失败分别存放在**构造时定容**的环形缓冲里；容量是明确的、可配置的硬上限。
- 写入超过容量后按时间顺序**挤掉最老**的一条，整体内存占用恒定为
  `SampleCapacity × sizeof(Frame)` 与 `FailureCapacity × sizeof(Failure)`，
  与进程跑了多久、累计采了多少帧无关。
- `Stats` 同时给“当前条数”和“累计条数”，二者之差就是被挤掉的数量；
  累计计数只增不减，可用于判断淘汰速率。

### 6.2 读取约定（不打断采集、帧完整、空结果可分辨）

- **互不阻塞、无空转**：采集 goroutine 不与读取方共享通道、不等待读取方；
  查询方法只在一把短临界区锁内做定长切片的值拷贝（不做任何 IO），
  因此读取不会卡住或打断在途采样，反之亦然。两次采样尝试之间用定时器
  休眠 `RetryInterval`，不是忙等。
- **帧完整有序**：返回的每个 `Frame{Seq, Stored, Sample}` 都是独立值拷贝；
  `Seq` 在 Observer 生命周期内从 1 严格单调递增，调用方可据此校验顺序与完整性，
  读不到半帧、字段对不上或乱序。
- **两种“空”严格区分**，由 `Batch.Status` 表达，绝不糊成同一个空切片：
  - `EMPTY`：启动至今确实还没采到任何一帧；
  - `EVICTED`：游标指向的帧已经被更新的数据挤出缓存。此时应丢弃旧游标，
    用 `Recent` 取当前快照后用新的 `NextCursor` 重新接续；
  - `OK`：正常；游标之后暂无新帧时 `Frames` 是空切片（不是错误）。
- 增量读法：`Since(0, n)` 取首批，之后把上一批 `NextCursor` 传回即可只拿新帧；
  `max` 限制单批条数，天然支持分批续读。

### 6.3 失败归因（稳定、可区分、可复盘）

- 根因仍由 `sensor`/`hal` 归一化（见第 4 节映射表），观测层只如实记录，
  **同一套设备状态与总线行为反复跑，结论不随调度早晚变化**。
- “设备在等待窗口里一直没准备好”与“调用方主动结束本次采集”分开：
  - 采样窗口到期（即使截止点恰好落在一次在途总线事务内）一律归 `TIMEOUT`；
  - 调用方 ctx 结束一律归 `CANCELED`。驱动在返回前按“父 ctx 是否仍有效”
    做最终判定，消除截止点落在轮询休眠还是在途事务里的时序差异。
- 采集循环对 `CANCELED` 的处理：若设备此刻已不在 ACTIVE（`Suspend/Shutdown`
  会主动取消在途采样），这属于电源切换的正常副作用，**不另记一条设备失败**
  （下一轮自然遇到并记录 `SUSPENDED/POWERED_OFF`）；仅当设备仍 ACTIVE 却被
  异常取消时才记录。调用 `Stop` 结束采集永远不会产生失败记录。
- 每条 `Failure{Seq, T, Code, Op, Message, Attempts}` 都留在有界失败环里，
  与近期采样一起用 `Failures()` 取回做现场复盘。设备侧失败不杀死采集进程：
  记录后休眠一个 `RetryInterval` 再继续，进程不空转、不中断。

## 7. 本地验证方法

```bash
go test ./...                 # 全部用例（正常路径 + 全部异常链路）
go test -race ./...           # 数据竞争检测
go test ./... -count=5        # 重复运行确认无时序抖动
go test ./... -v              # 打印总线读写激励与状态迁移日志
go vet ./... && gofmt -l .    # 静态检查与格式
```

测试覆盖矩阵：

- 正常：探测 / 初始化 / 回读 / 采样（时间戳、确定性数据、ODR/FSR 回传）
- 异常：总线超时（先失败后成功 / 重试耗尽 / 尝试次数留痕）、设备拒绝（不重试）、
  回读不一致（篡改）、非法配置（零总线事务）、版本不兼容四种原因、
  采样就绪超时、调用方取消
- 电源：挂起期间访问立即失败且不触总线、恢复后无陈旧数据、
  突发掉电后 Resume 触发完整重新初始化、非法状态迁移、挂起失败不产生假迁移
- 并发：16 路并发采样无竞争且帧序单调；在途采样被 Suspend 取消（Suspend 不阻塞）
- 长时：20 帧连续采样后取消，goroutine 回落；挂起后流吐出终态错误并关闭
- 观测层：容量上限/FIFO 淘汰后条数恒定、`Recent(n)` 截断、
  `EMPTY` 与 `EVICTED` 可分辨、`Since` 游标分页续读、快照不可被外部改写；
  采集循环写入完整有序帧、失败记录可查且有界、`Stop` 不产生 CANCELED 记录、
  挂起/恢复跨周期续采、读取方并发快照不打断采集（`-race`）、
  goroutine 停止后回收
- 归因稳定性：采样窗口截止点落在在途事务内仍稳定归 `TIMEOUT`，
  调用方取消稳定归 `CANCELED`（同一故障配置重复 5× 结论一致）
