# sensor-hal-go

纯本地、零外部依赖的加速度传感器驱动与硬件抽象层（HAL）。硬件由**内存映射
寄存器总线**模拟，不需要真实硬件或外部服务即可完成设备探测、初始化、采样、
寄存器映射版本兼容判定与电源状态切换。

- `bus`：内存寄存器总线（16 位寄存器、单读/单写/突发读、事务日志、确定性故障注入）
- `sensor`：设备驱动（探测/初始化/采样、版本兼容、写后回读、仅读重试、电源状态机）、
  以及确定性的模拟设备模型 `SimDevice`
- `hal`：对外门面（归一化错误码、并发串行化采样、挂起取消在途操作、长时连续采样流、
  面向连续运行数日以上进程的**长期观测层**：定容最近采样环 + 定容失败记录环）

## 1. 适用总线模型

- 寻址：8 位寄存器地址，16 位寄存器值。
- 事务：`Read(addr)`、`Write(addr,val)`、`ReadBurst(addr,n)`。
  所有事务在总线单锁内串行完成；**突发读在同一临界区内取数，不存在撕裂读**。
- 设备模型：`bus.Model` 挂接在总线上模拟设备行为（电源状态机、按 ODR 产生数据、
  OVERRUN/RCAL 状态位）。模型可实现 `bus.WriteGate` 在掉电时拒绝写入。
- 可观测：每次事务都记录到 `Log()`：序号、类型、地址、值、故障、时间戳，
  单测通过 `-v` 打印全部读写激励；驱动还会打印 `PROBE/SAMPLE/STATE` 迁移日志。
- 故障注入：`FaultRule{Kind, Addr, Times, Fault, Delay}` 可精确注入
  `TIMEOUT / REJECT / CORRUPT`，`Times` 控制前 N 次命中（用于“先失败后成功”）。
  - `REJECT`：事务被拒绝，寄存器不变、设备模型不触发；
  - `CORRUPT`：写时设备收到的是取反值（读回必然不一致），读时返回取反值；
  - `TIMEOUT`：等待 `Delay` 后返回 `bus.ErrTimeout`，等待可被 ctx 取消。

## 2. 版本兼容规则

版本编码为 `Major<<8 | Minor`（寄存器 `0x01`）。驱动编译期版本为 `2.1`，
判定只取决于入参，结果确定、拒绝原因彼此可区分：

| 设备情况 | 结论 | 原因（CompatReason） |
| --- | --- | --- |
| 芯片 ID 未知 | 拒绝 | `UNKNOWN_CHIP` |
| 版本寄存器为 `0xFFFF` | 拒绝 | `VERSION_UNREADABLE` |
| Major 不同（更新或更旧） | 拒绝 | `MAJOR_MISMATCH` |
| Major 相同，设备 Minor 更旧 | 拒绝 | `DEVICE_TOO_OLD` |
| Major 相同，Minor 相同或更新 | **接受** | `OK` |

- **较新 Minor 接受**：Minor 升级只允许在寄存器映射尾部追加字段，
  `Config.ODR/FSR` 等既有字段的地址与语义不变，因此不会静默改变既有语义。
- **较新 Major 拒绝**：Major 变化允许重新定义既有字段，驱动无法保证语义一致。
- 不兼容时 `Probe/Init` 均返回 `KindIncompatible`，设备不会进入 ACTIVE。

## 3. 电源状态迁移

```
                 Init(合法配置+版本兼容+回读一致)
   OFF  ───────────────────────────────────────────► ACTIVE
    ▲     PowerOff(0x03=0)             Suspend(0x03=POWER|SUSPEND)
    └──────────────────────────┐    ┌───────────────────────────┐
                               ◄────┘                           ▼
                             ACTIVE ◄──────────────────── SUSPENDED
                                  Resume(0x03=POWER)
```

- 仅 `ACTIVE` 可采样。
- **挂起期间**：`Sample/Init/Probe/Suspend` 立即返回 `SUSPENDED`，
  不发起任何总线事务、不返回陈旧数据。
- **Resume**：先上电，再读配置签名寄存器 `0x1F`（`0xC0FE`）。
  签名丢失（突发掉电）则按驱动保存的配置**完整重新初始化**，
  不沿用内存里的旧状态；签名仍在则直接回到 ACTIVE。
- **PowerOff** 幂等；掉电后只有重新 `Init` 才能使用，采样返回 `POWERED_OFF`。
- 迁移过程中的总线失败不会产生虚假状态迁移（如挂起失败仍停留在 ACTIVE）。
- `SimDevice.SimulatePowerLoss(bus)` 可确定性模拟挂起期间的突发掉电
  （Ctrl/ODR/FSR/签名/数据/状态寄存器全部复位）。

HAL 层额外保证：`Suspend/Shutdown` 会**取消在途采样**，因此不会被长采样阻塞；
采样通过容量 1 的令牌串行化，获取令牌本身也可被 ctx 取消。

### 3.1 挂起/恢复打断在途采样的归因规则（设备侧 vs 调用方）

`Suspend/Shutdown` 取消在途采样时，取消来自**设备侧电源切换**，与调用方
主动取消自己的 ctx 是两种必须可分的结论。HAL 为每次在途采样持有一张
**在途票据**：电源切换在真正取消采样上下文之前，先在票据上写下设备侧原因
（挂起=`SUSPENDED`、关电=`POWERED_OFF`），采样醒来后据此归因：

| 情形 | 结论 Code |
| --- | --- |
| 调用方 ctx 已结束（主动取消 / 调用方自己的截止），即使电源切换同时发生 | `CANCELED` |
| 调用方 ctx 存活，采样被 `Suspend` 打断（无论挂起落在读事务的哪个时刻） | `SUSPENDED` |
| 调用方 ctx 存活，采样被 `Shutdown` 打断 | `POWERED_OFF` |
| 采样发起时设备已挂起 / 已掉电（立即失败、不触总线） | `SUSPENDED` / `POWERED_OFF` |

因此同一次挂起，无论它打断的是总线读、就绪轮询睡眠，还是下一次重建的流
恰好落在设备已挂起之后，结论**恒为 `SUSPENDED`**，不随调度先后、不随
挂起落在采样过程的时刻而在 `CANCELED`/`SUSPENDED` 之间漂移；两者比例
在反复压测中恒定（挂起相关记录里 `CANCELED` 恒为 0）。挂起写总线本身失败、
设备未真正离开 ACTIVE 时，电源操作返回真实总线错误且不发生虚假状态迁移。

## 4. 错误分类与重试/副作用规则

根因在进入对外接口前归一化，不同调用路径遇到同类根因得到同一错误码。

| 根因 | sensor.Kind | hal.Code |
| --- | --- | --- |
| 总线超时 | `TIMEOUT` | `TIMEOUT` |
| 设备拒绝（如下电时写） | `REJECTED` | `REJECTED` |
| 写后回读不一致 | `READBACK_MISMATCH` | `READBACK_MISMATCH` |
| 配置非法（枚举之外） | `BAD_CONFIG` | `BAD_CONFIG` |
| 版本不兼容 | `INCOMPATIBLE` | `INCOMPATIBLE` |
| 挂起中访问 | `SUSPENDED` | `SUSPENDED` |
| 掉电访问 | `POWERED_OFF` | `POWERED_OFF` |
| 其他 IO 错误 | `IO` | `IO` |
| 调用方取消/超时 | `CANCELED` | `CANCELED` |

重试与副作用约定：

- **只有读事务允许重试，且只对总线超时重试**（默认 2 次额外尝试，共 3 次）；
  拒绝、取消、不兼容等立即返回。终态错误带 `Attempts` 计数，`Retryable=false`，
  失败不被重试掩盖。
- **写事务一次定音、绝不重试**，因此不会产生重复写副作用；每次写后立即读回校验，
  不符即 `READBACK_MISMATCH`（线上被 CORRUPT 时设备存的是取反值，读回必然失败）。
- 非法配置在触碰总线之前就被拒绝（验证用例断言总线日志为 0 条）。

采样结果 `Sample` 带：墙钟时间戳 `T`、三轴 `X/Y/Z`、配置快照 `ODR/FSR` 与
质量标记 `QOK / QOverrun（旧帧被新帧覆盖）/ QNeedsRecal`。
数据就绪采用“读状态位 → 休眠 `PollInterval` → 再读”的有界轮询
（默认 1ms 间隔、200ms 上限），**没有忙等**。设备在该窗口内一直未就绪，
结论恒为 `TIMEOUT`：即使内部截止恰好打断一次在途读事务，只要外层调用方 ctx
仍然存活，驱动就把它归为 `TIMEOUT` 而非 `CANCELED`，归因不随调度先后变化；
只有外层调用方主动取消/自己的截止到期才是 `CANCELED`。

## 5. 并发与长时运行

- 总线事务串行、突发读原子；驱动全部方法在互斥锁下推进状态机。
- HAL 同一时刻只允许一个采样事务在途（并发 `Read` 被串行化），
  在 `-race` 下验证无数据竞争，且连续帧序列值严格递增，不会两调用读到同一帧。
  每次在途采样持有一张 HAL 票据：`Suspend/Shutdown` 经 `pmu` 串行执行，
  在取消在途采样前于票据上记下设备侧原因（见 3.1 节），票据由所属 `Read`
  独占、结束时注销，因此设备侧中断归因不依赖事后读取设备状态、无竞态窗口。
- `Stream(ctx)` 只启动一个 goroutine、输出无缓冲通道；帧间释放采样令牌，
  挂起/关电可插入。遇到挂起/掉电等终态时下发一条错误并关闭通道，不空转；
  ctx 取消后 goroutine 必然退出、通道必然关闭，测试断言 goroutine 数量回落到基线。

测试覆盖矩阵：

- 异常：总线超时（先失败后成功 / 重试耗尽 / 尝试次数留痕）、设备拒绝（不重试）、

  采样就绪超时、调用方取消

- 长时：20 帧连续采样后取消，goroutine 回落；挂起后流吐出终态错误并关闭

## 7. 长期运行观测层（Observer）

`hal.Observer` 在不改既有单次操作语义的前提下，叠加一层面向边缘采集进程的观测
能力：一个后台采集泵持续采样，成功帧进入**最近采样环**，失败进入**失败记录环**，
现场排查时与总线日志一起复盘。

```go
o := hal.NewObserver(h, hal.ObserverConfig{
    SampleCapacity:  1024, // 最近采样保留条数上限（<=0 取默认 1024）
    FailureCapacity: 128,  // 失败记录保留条数上限（<=0 取默认 128）
    RestartWait:     100 * time.Millisecond, // 终态后重建流前的等待
})
o.Start(ctx)        // 启动唯一的后台采集 goroutine
defer o.Close()     // 停止并等待 goroutine 退出（不动设备电源状态）

o.Recent(50)        // 最新 50 帧快照（从老到新）；max<=0 取全部保留帧
o.Since(cursor)     // 增量拉取，见下方四种状态
o.RecentFailures(0) // 失败记录快照
o.Stats()           // 容量占用：Count/Dropped/容量上限
```

### 7.1 容量规则（占用平稳、可配置）

- 两个环都是**构造时定容的固定数组**，容量显式可配、非法/零值归一化为默认值。
- 每推入一条，若已满则**按时间顺序把最老的一条原地挤出**（FIFO）：
  保留条数恒为 `min(累计产量, 容量)`，不会因为连跑几天而持续堆内存；
  `Stats().*Dropped` 单调记录被挤掉的条数，长期运行曲线平稳。
- 每条采样带一个**从 1 开始、单调递增、绝不复用的序号**：旧帧被挤出后新帧
  序号继续增大，调用方据此判断自己错过的区间。失败记录有独立的序号空间。

### 7.2 读取约定（不打断采集、不忙等、帧完整、状态可分）

- 采集泵只有一个长期 goroutine，复用 `HAL.Stream`：帧级串行、挂起/关电可插入。
  流在终态错误后关闭，**休眠 `RestartWait` 再重建**（定时器等待，非忙等/空转）；
  `Close` 可立即打断该等待，goroutine 必然退出（有 goroutine 回落断言）。
- 泵只在“把一帧塞进环”的瞬间短暂持锁；**读总线、等待数据就绪期间不持锁**。
  `Recent/Since/RecentFailures/Stats` 全部返回**新分配的快照副本**，
  因此查询不会被采集阻塞、也不会打断/卡住在途采集，采集方也不等待查询方；
  高查询负载下采集持续推进有测试断言，`-race` 下无竞争。
- 每帧来自一次原子突发读（见第 1 节），入环的是完整 `Sample` 值拷贝，
  因此读出来的每条都是**字段自洽、前后一致的一帧**，不存在半帧或新旧字段拼装；
  帧按入环时间从老到新、序号连续。
- `Since(cursor)` 用四种状态把两种“空”明确分开，绝不糊成同一个空结果：

| 状态 | 含义 |
| --- | --- |
| `NO_DATA` | Observer 自启动以来**确实还没有任何采样** |
| `MISSED` | cursor 指向的（部分）帧**已被更新数据挤出**；返回当前仍保留的整个窗口与新边界，调用方应拿最后一帧序号重置游标 |
| `CURRENT` | cursor 已是最新，其后暂时还没有新帧（正常空转检查，非丢数据） |
| `OK` | 正常返回严格晚于 cursor、当前仍保留的帧 |

  cursor 传 0 表示从头取；尚未产出任何帧时仍为 `NO_DATA`。

### 7.3 失败归因（结论稳定、可区分、留痕）

- 失败记录直接沿用 HAL 的归一化错误码（第 4 节）：**同一套设备状态与总线行为，
  无论内部截止时间与某次总线读事务谁先谁后，结论一致**。例如“设备在采样就绪
  窗口内一直没准备好”恒为 `TIMEOUT`——即便内部截止恰好打断在途读，驱动也会
  把该情形从 `CANCELED` 校正回 `TIMEOUT`（外层调用方 ctx 仍活着时）。
- **设备挂起打断在途采样（`SUSPENDED`）与调用方主动结束（`CANCELED`）
  明确分开且结论稳定**：`Suspend/Shutdown` 在取消在途采样前先在 HAL 在途
  票据上记下设备侧原因（见 3.1 节）。因此反复挂起/恢复压测下，无论挂起
  打断的是在途总线读还是就绪轮询、也无论两次操作落在采样过程的哪个时刻，
  失败记录恒为 `SUSPENDED`，不会时而成 `CANCELED`，归因与比例不随调度
  漂移；`Shutdown` 打断同理恒为 `POWERED_OFF`。只有外层调用方 ctx 结束
  （主动取消/调用方自己的截止）才记 `CANCELED`。
- Observer 因 `Close` / 启动 ctx 取消而结束是**调用方主动停止采集，不入失败环**；
  挂起/掉电等设备侧终态（流上为 `SUSPENDED`/`POWERED_OFF` 等）才写入失败
  记录，记录含：失败序号、墙钟时间、错误码、操作名、尝试次数、详情。
  挂起期间设备一直不产帧：流以终态错误结束、休眠 `RestartWait` 后重建，
  每个挂起窗口只留下同一种 `SUSPENDED` 结论；恢复后采样正常接续，
  帧序号严格连续、不回退、不混入陈旧/乱序帧。
- 失败环同样定容 FIFO，`RecentFailures` 与 `Recent` 按时间戳/序号对齐复盘。

```bash
go test ./...                 # 含观测层：容量/挤出、Since 四态、帧完整、
                              # 失败归因、并发不阻塞、挂起恢复、goroutine 回收

go vet ./... && gofmt -l .    # 静态检查与格式
```

观测层新增覆盖：

- 容量：推入远超容量后保留条数恒等于上限、`Dropped` 正确、再跑一段占用仍平稳；
  `Recent(max)` 只取最新若干条且与环存储不别名；容量/等待默认值归一化
- 查询：`NO_DATA / MISSED / CURRENT / OK` 四态可分；MISSED 仍返回保留窗口；
  游标在窗口中间时首帧序号恰为 cursor+1
- 完整性：环内序号连续；每帧三轴共同对应同一设备帧（撕裂/半帧会对不上），
  配置快照与时间戳齐全；设备帧严格递增
- 失败：设备持续超时时直接读与后台记录**稳定为 TIMEOUT**（连跑 10 次不翻
  `CANCELED`）；调用方先取消自己 ctx 得到 `CANCELED` 且不污染失败环；
  失败环定容、失败序号单调
- 并发/电源：8 路查询并发下采集持续推进；挂起期间不产新帧、失败留痕、
  历史不丢；恢复后帧序号严格接续；多次挂起/恢复反复重建流后 `Close`，
  goroutine 回落到基线
- **挂起归因压测（`hal/suspend_attribution_test.go`）**：
  - 直接路径连续 20 轮：在途采样被挂起打断恒为 `SUSPENDED`，交替覆盖
    “先收到错误再取消调用方 ctx / 先取消再收到错误”两种调度先后；
    挂起后新发起的读同样立即得 `SUSPENDED`；恢复后可正常采样；
